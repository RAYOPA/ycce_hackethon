# 🤖 ManRakshak AI — AI Engine Documentation

## Overview

ManRakshak uses a **two-layer AI architecture**:

1. **XGBoost ML Model** — Trained on personnel wellness data to predict stress/burnout risk
2. **LLM Chat Gateway** — OpenRouter (Qwen 3.8-27B) for conversational wellness support

Both systems are integrated into the FastAPI backend and operate with strong privacy and safety controls.

## 🧠 Layer 1: XGBoost Risk Prediction Engine

### Location
- Training code: `ai_engine/model.py`
- Backend integration: `backend/app/ai/`
- Trained models: `models/` (generated by training, not committed to git)

### Model Architecture

```
Input Features (13)
       │
       ▼
Feature Engineering
(Temporal baselines, deviations)
       │
       ▼
XGBoost Classifier
(n_estimators=100, max_depth=4, lr=0.1)
       │
       ▼
Calibrated Classifier CV
(Sigmoid calibration, cv=3)
(Ensures reliable probability outputs)
       │
       ▼
Risk Probability [0.0 - 1.0]
  ├── < 0.5  → "Normal"
  └── ≥ 0.5  → "Elevated"
       │
       ▼
SHAP TreeExplainer
→ Top-3 human-readable risk factors
```

### Features (13 Input Variables)

| Feature | Type | Description |
|---|---|---|
| `deployment_duration_months` | Integer | Months in current deployment posting |
| `duty_duration_hrs` | Float | Today's total duty hours |
| `consecutive_duty_days` | Integer | Days in a row without off |
| `night_duty` | Boolean (0/1) | Whether on night shift |
| `leave_gap_days` | Integer | Days since last approved leave |
| `training_load` | Integer (1-5) | Training intensity rating |
| `sleep_hours` | Float | Hours slept last night |
| `mood_score` | Integer (1-10) | Self-reported mood |
| `workload_perception` | Integer (1-10) | Self-reported workload stress |
| `sleep_deviation` | Float | Current sleep vs. personal 7-day baseline |
| `mood_deviation` | Float | Current mood vs. personal 7-day baseline |
| `workload_deviation` | Float | Current workload vs. personal 7-day baseline |
| `consecutive_night_duties_7d` | Integer | Night duties in last 7 days (rolling sum) |

### Temporal Feature Engineering

Personal baselines are computed dynamically to detect **relative changes** (not just absolute values):

```python
# 7-day rolling personal baseline (lag-1 to prevent data leakage)
df['sleep_baseline_7d'] = df.groupby('personnel_id')['sleep_hours'].transform(
    lambda x: x.shift(1).rolling(7, min_periods=1).mean()
)

# Deviation from baseline
df['sleep_deviation'] = df['sleep_hours'] - df['sleep_baseline_7d']
```

This means: if a person normally sleeps 7 hours and sleeps 4 hours, the deviation of -3 is a strong risk signal — regardless of population averages.

## 💬 Layer 2: LLM Chat Gateway (OpenRouter)

### Overview

The AI chat system routes through **OpenRouter** to access the `qwen/qwen3.8-27b:free` model. This provides conversational support to users while operating behind multiple safety layers.

### Architecture

```
User Chat Message
       │
       ▼
   AI Firewall (app/ai/firewall.py)
   └── Reject: harmful content, prompt injection, crisis terms
   └── Reject: content not related to wellness/police work
       │
       ▼
   Privacy Filter (app/ai/privacy.py)
   └── Strip PII from user context
   └── Anonymize personnel identifiers
       │
       ▼
   AI Gateway (app/ai/gateway.py)
   └── Provider factory (selects OpenRouterProvider)
       │
       ▼
   OpenRouter Provider (app/ai/providers/openrouter.py)
   └── POST https://openrouter.ai/api/v1/chat/completions
   └── Model: qwen/qwen3.8-27b:free
   └── Timeout: 30 seconds
       │
       ▼
   LLM Response
       │
       ▼
   Safety Post-Filter
   └── Strip any leaked PII
   └── Validate response format
       │
       ▼
   Return to User
```

### Configuration

```env
# backend/.env
AI_PROVIDER=openrouter
OPEN_ROUTER_API_KEY=sk-or-v1-your-key-here
OPEN_ROUTER_MODEL=qwen/qwen3.8-27b:free
OPEN_ROUTER_BASE_URL=https://openrouter.ai/api/v1
AI_REQUEST_TIMEOUT_SECONDS=30.0
```

Get your API key at: https://openrouter.ai/keys

The `qwen/qwen3.8-27b:free` model is available at **zero cost** on OpenRouter's free tier.

### AI Firewall (`app/ai/firewall.py`)

The firewall prevents misuse of the AI chat system:

- **Blocks crisis language** — routes to human support instead of LLM
- **Blocks prompt injection** — prevents jailbreaking attempts
- **Blocks off-topic requests** — keeps AI focused on wellness support
- **Content safety filtering** — prevents generation of harmful content

### Provider Interface

Future AI providers can be added without changing business logic:

```python
# app/ai/interfaces.py
class AIProvider(ABC):
    @abstractmethod
    async def chat(self, messages: list[dict], **kwargs) -> AIResponse:
        ...
    
    @abstractmethod
    async def predict_risk(self, features: dict) -> RiskPrediction:
        ...
```

```python
# app/ai/gateway.py — Registry
_PROVIDER_REGISTRY = {
    "openrouter": OpenRouterProvider,
    # Future providers:
    # "stress_ml": StressMLProvider,
    # "google_vertex": VertexAIProvider,
}
```

### Adding a New AI Provider

1. Create `backend/app/ai/providers/<name>.py` implementing `AIProvider`
2. Register in `gateway.py`'s `_build_registry()`
3. Set `AI_PROVIDER=<name>` in `backend/.env`
4. No other changes needed

## 🔒 AI Privacy & Ethics

### Privacy Principles

1. **No raw PII to LLM** — all personally identifiable data is stripped before sending to OpenRouter
2. **SHAP explanations** use feature names, not personal identifiers
3. **Risk scores stored** in the wellness_checkins table are used only for authorized welfare officers
4. **AI predictions are advisory** — final decisions always require human review

### Ethical Guardrails

- AI risk assessment is a **support tool**, not a replacement for human judgment
- All AI-generated interventions are flagged as AI-suggested and require human approval
- Personnel are informed that their data is used for wellness monitoring (consent at registration)
- Risk data is never shared with HR for punitive purposes (governed by privacy_policy.py)
